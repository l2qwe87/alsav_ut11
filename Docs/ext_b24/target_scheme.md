# Целевая схема синхронизации 1С и Битрикс24

## Общий принцип
Синхронизация осуществляется по принципу "ведущая система 1С" - все изменения создаются в 1С и выгружаются в Б24.

## Процесс создания новых сущностей

### Шаг 1. Создание в 1С
Пользователь создаёт новую сущность в 1С:
- **Партнёр**
- **Контрагент**
- **Контактное лицо**

### Шаг 2. Выгрузка в Б24
Система автоматически выгружает данные в Битрикс24:
- Определяется тип сущности для Б24:
  - Партнёр → Компания в Б24
  - Контрагент → Контакт в Б24
  - Контактное лицо → Контакт в Б24
- Создаётся соответствующая сущность в Б24

### Шаг 3. Фиксация идентификаторов

#### В 1С (Регистр сведений)
В регистре **алсавб24_СопоставлениеКлиентов** сохраняется:
- **Объект1С** - ссылка на партнёра/контрагента/контактное лицо
- **ИдентификаторБ24** - ID созданной сущности в Б24
- **ТипСущностиБ24** - COMPANY/CONTACT
- **ДатаСинхронизации** - время последней синхронизации

#### В Б24 (Поля сущности)
В созданной сущности заполняются поля:
- **Идентификатор1С** - уникальный GUID объекта справочника 1С
- **ТипОбъекта1С** - Партнёр/Контрагент/КонтактноеЛицо
- **ДатаОбновления** - время последнего обновления из 1С

## Обновление существующих сущностей

### Изменение в 1С
При изменении данных партнёра/контрагента в 1С:
1. Система находит соответствие в регистре сведений
2. Получает ID сущности в Б24
3. Обновляет данные в Б24 через API
4. Обновляет дату синхронизации в регистре
