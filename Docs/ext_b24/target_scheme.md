# Целевая схема синхронизации 1С и Битрикс24

## Общий принцип
Синхронизация осуществляется по принципу "ведущая система 1С" - все изменения создаются в 1С и выгружаются в Б24.

## Соответствие сущностей
| 1С:Предприятие | Битрикс24 | Обработка выгрузки |
|---------------|-----------|-------------------|
| Партнёр | Смарт-процесс | алсавб24_ВыгрузкаПартнеров |
| Контрагент | Компания | алсавб24_ВыгрузкаКонтрагентов |

## Процесс создания новых сущностей

### Шаг 1. Создание в 1С
Пользователь создаёт новую сущность в 1С:
- **Партнёр** - для выгрузки в смарт-процесс Б24
- **Контрагент** - для выгрузки в компанию Б24

### Шаг 2. Выгрузка в Б24
Система выгружает данные в Битрикс24 через соответствующие обработки:
- **Партнёр → Смарт-процесс** через `алсавб24_ВыгрузкаПартнеров`
- **Контрагент → Компания** через `алсавб24_ВыгрузкаКонтрагентов`

### Шаг 3. Фиксация идентификаторов

#### В 1С (Регистр сведений алсавб24_СопоставлениеКлиентов)
Структура регистра:
- **ID** (измерение) - идентификатор сущности в Б24
- **Партнер** (ресурс) - ссылка на партнера 1С
- **TITLE** (ресурс) - наименование сущности в Б24
- **ПохожийПартнер1-3** (ресурсы) - возможные дубли для ручного сопоставления

#### В Б24 (Поля сущности)
В созданной сущности заполняются поля:
- **ORIGIN_ID** - GUID объекта справочника 1С
- **ORIGINATOR_ID** - "1С8 УТ11"
- **ORIGIN_VERSION** - навигационная ссылка на объект 1С

## Алгоритм выгрузки

### Для Партнеров (алсавб24_ВыгрузкаПартнеров)
1. **Проверка сопоставления** - поиск в регистре по ссылке на партнера
2. **Поиск в Б24** - поиск смарт-процесса по ORIGIN_ID
3. **Подготовка полей**:
   - TITLE - наименование партнера
   - CONTACT_INFO - телефоны, email, веб-сайты
   - COMMENTS - комментарий партнера
   - ORIGIN_ID, ORIGINATOR_ID, ORIGIN_VERSION
4. **Создание/обновление** - вызов API смарт-процессов
5. **Регистрация** - сохранение сопоставления в регистр

### Для Контрагентов (алсавб24_ВыгрузкаКонтрагентов)
1. **Проверка сопоставления** - поиск в регистре по ссылке на контрагента
2. **Поиск в Б24** - поиск компании по ORIGIN_ID
3. **Подготовка полей**:
   - TITLE - наименование контрагента
   - PHONE, EMAIL, WEB - контактная информация
   - RQ_INN, RQ_KPP - юридические реквизиты
   - COMMENTS - комментарий контрагента
   - ORIGIN_ID, ORIGINATOR_ID, ORIGIN_VERSION
4. **Создание/обновление** - вызов API компаний
5. **Регистрация** - сохранение сопоставления в регистр

## Обновление существующих сущностей

### Изменение в 1С
При изменении данных партнера/контрагента в 1С:
1. Система находит соответствие в регистре сведений по ссылке на объект
2. Получает ID сущности в Б24 из измерения регистра
3. Подготавливает обновленные поля для API
4. Вызывает метод обновления соответствующей сущности в Б24
5. Обновляет запись в регистре (при необходимости)

## Механизмы интеграции

### API модули
- **алсавб24_Http** - выполнение HTTP запросов к Б24
- **алсавб24_Json** - преобразование JSON в структуры 1С
- **алсавб24_api_CRM_Компании** - методы работы с компаниями Б24

### Обработка ошибок
- Стандартные формы ошибок 1С:Предприятие
- Отсутствие блоков Попытка-Исключение для перехвата ошибок
- Позволение платформе обрабатывать исключения стандартными средствами

## Ограничения
- Синхронизация только из 1С в Б24 (односторонняя)
- Не синхронизируются контакты и контактные лица
- Используются только стандартные поля сущностей Б24
