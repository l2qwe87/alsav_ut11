# Примеры использования 1c-metadata

## Сценарий 1: Анализ перед изменением справочника

### Задача
Добавить новый реквизит в справочник "Номенклатура".

### Порядок действий
1. **Найти справочник и связанные объекты**
```bash
/search_metadata query="Номенклатура" metadataType="Catalogs"
```

2. **Проверить использование в документах**
```bash
/search_metadata query="Номенклатура" metadataType="Documents"
```

3. **Найти формы и модули**
```bash
/find_object_by_name objectName="Номенклатура"
```

### Ожидаемый результат
- Найдены все формы справочника
- Определены документы, использующие номенклатуру
- Выявлены связанные модули обработки

---

## Сценарий 2: Рефакторинг общего модуля

### Задача
Переименовать функцию в общем модуле "алсав_ВыгрузкаCsvJson".

### Порядок действий
1. **Найти модуль**
```bash
/search_metadata query="алсав_ВыгрузкаCsvJson" metadataType="CommonModules"
```

2. **Найти все использования**
```bash
/search_metadata query="алсав_ВыгрузкаCsvJson"
```

3. **Проверить структуру**
```bash
/get_metadata_structure path="ext_alsav/CommonModules"
```

### Ожидаемый результат
- Найден файл модуля
- Определены все места использования функции
- Получена структура для понимания контекста

---

## Сценарий 3: Поиск зависимостей регистра

### Задача
Проанализировать регистр "ВыручкаИСебестоимостьПродаж".

### Порядок действий
1. **Найти регистр**
```bash
/find_object_by_name objectName="ВыручкаИСебестоимостьПродаж"
```

2. **Найти документы, делающие движения**
```bash
/search_metadata query="ВыручкаИСебестоимостьПродаж" metadataType="Documents"
```

3. **Найти отчеты, использующие регистр**
```bash
/search_metadata query="ВыручкаИСебестоимостьПродаж" metadataType="Reports"
```

### Ожидаемый результат
- Найден регистр накопления
- Определены документы для движения
- Выявлены отчеты для анализа данных

## Сценарий 4: Анализ конфигурации перед миграцией

### Задача
Оценить сложность миграции конфигурации.

### Порядок действий
1. **Получить полную структуру**
```bash
/get_metadata_structure
```

2. **Проанализировать подсистемы**
```bash
/search_metadata query="CRM" metadataType="Subsystems"
```

3. **Найти кастомные объекты**
```bash
/search_metadata query="алсав_"
```

### Ожидаемый результат
- Полная структура метаданных
- Список подсистем для миграции
- Кастомные объекты требующие особого внимания

## Сценарий 5: Поиск неиспользуемых объектов

### Задача
Найти потенциально неиспользуемые справочники.

### Порядок действий
1. **Получить список всех справочников**
```bash
/get_metadata_structure
```

2. **Для каждого справочника проверить использования**
```bash
/search_metadata query="ИмяСправочника"
```

3. **Анализ результатов**
- Справочники без использований в документах
- Отсутствие ссылок в модулях
- Неиспользуемые в формах

### Ожидаемый результат
- Список кандидатов на удаление
- Обоснования для каждого объекта
- Рекомендации по дальнейшим действиям

---

## Сценарий 6: Влияние изменений на подсистему

### Задача
Оценить влияние изменения общего модуля на подсистему "Продажи".

### Порядок действий
1. **Найти объекты подсистемы**
```bash
/search_metadata query="Продажи" metadataType="Subsystems"
```

2. **Найти связанные модули**
```bash
/search_metadata query="алсав_" metadataType="CommonModules"
```

3. **Найти документы подсистемы**
```bash
/search_metadata query="Продажа" metadataType="Documents"
```

### Ожидаемый результат
- Карта зависимостей подсистемы
- Критичные изменения требующие внимания
- Объекты для регрессионного тестирования

---

## Рекомендации по анализу результатов

### Интерпретация результатов
1. **Количество найденных объектов** - показывает популярность использования
2. **Типы метаданных** - помогает понять сферу влияния
3. **Пути к файлам** - необходимы для прямого доступа к объектам

### Критерии принятия решений
- **Минимальное влияние** - < 5 использований
- **Среднее влияние** - 5-20 использований  
- **Критичное влияние** - > 20 использований

### Действия после анализа
1. **Документирование** - сохраните результаты анализа
2. **Планирование** - определите порядок изменений
3. **Тестирование** - выделите объекты для проверки
4. **Резервирование** - создайте бэкапы перед изменениями
