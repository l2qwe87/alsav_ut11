# AGENTS.md

## Информация о проекте

### Язык разработки
- Разработка ведётся на платформе 1С:Предприятие

### Правила работы с Git
- **ВАЖНО**: Не создавать коммиты в main
- **ВАЖНО**: Не мёржить PR
- Описания коммитов и PR делать на русском языке
- Создавать PR утилитой `gh pr` с флагом `--body-file file`
- Описание PR предварительно сохранять в файл
- После создания PR удалять временный файл
- **ВАЖНО**: Временные файлы описания PR не коммитить в репозиторий



### Структура проекта
- `ext_alsav/` - основное расширение с бизнес-логикой (регистры накопления, бизнес-процессы, подсистемы CRM, закупок, продаж, склада)
- `ext_b24/` - расширение для интеграции с Битрикс24 (модули HTTP/JSON, сопоставление клиентов)
- `base/` - базовая конфигурация (исключена из gitignore)

### Конвенции кода
- Следовать существующему стилю кода
- Использовать существующие библиотеки и утилиты
- Следовать паттернам проекта
- **Обработка исключений**: Не использовать блоки `Попытка-Исключение` для перехвата ошибок. Позволять платформе обрабатывать исключения стандартными средствами. Стандартные формы ошибок 1С:Предприятие являются приемлемыми для пользователей.

### Работа с метаданными 1С
- **ОБЯЗАТЕЛЬНО**: Перед изменением любого объекта метаданных использовать MCP сервер `1c-metadata` для анализа связей
- **ОБЯЗАТЕЛЬНО**: После изменения XML файлов метаданных проверять синтаксис с помощью инструмента `1c-syntax-checker`
- Использовать `search_metadata` для поиска зависимостей перед модификацией
- Использовать `get_metadata_structure` для понимания структуры конфигурации
- Использовать `find_object_by_name` для поиска связанных объектов

### Проверка синтаксиса и качества кода
- **ОБЯЗАТЕЛЬНО**: Проверять синтаксис всех измененных XML файлов с помощью `1c-syntax-checker`
- **ОБЯЗАТЕЛЬНО**: Выполнять проверку синтаксиса при генерации кода 1С (файлов *.bsl) через `1c-syntax-checker`
- Использовать MCP сервер `1c-help` для проверки корректности конструкций языка 1С
- Использовать `get_1c_syntax` для проверки синтаксиса конструкций (Если, Для, Пока и т.д.)
- Использовать `get_1c_examples` для получения примеров правильного кода
- Использовать `search_1c_help` для поиска информации о функциях и процедурах

### Порядок работы с изменениями
1. **Анализ**: Использовать `search_metadata` для поиска связанных объектов
2. **Изменение**: Вносить изменения в код с учетом существующих паттернов
3. **Проверка синтаксиса**: Использовать `1c-syntax-checker` для всех XML и BSL файлов
4. **Проверка кода**: Использовать `1c-help` MCP сервер для проверки конструкций 1С
5. **Тестирование**: Убедиться что все изменения корректны

### Доступные инструменты
- **MCP сервер 1c-metadata**:
  - `search_metadata` - поиск по метаданным
  - `get_metadata_structure` - структура конфигурации
  - `find_object_by_name` - поиск объектов по имени
- **Инструмент 1c-syntax-checker** - проверка синтаксиса XML файлов
- **MCP сервер 1c-help**:
  - `search_1c_help` - поиск по справке 1С
  - `get_1c_syntax` - синтаксис конструкций
  - `get_1c_examples` - примеры кода
  - `search_web_help` - онлайн-справка

### Правила работы с типами метаданных

#### Справочники (Catalogs)
- Перед изменением реквизитов использовать `search_metadata` для поиска форм и модулей
- Проверять наличие связанных документов через поиск по имени справочника
- После изменения обязательно проверять синтаксис XML файла справочника

#### Документы (Documents)
- Анализировать движения документов по регистрам через `search_metadata`
- Проверять связанные печатные формы и отчеты
- Убедиться что все реквизиты имеют корректные типы данных

#### Регистры (AccumulationRegisters, InformationRegisters)
- Проверять структуру измерений, ресурсов и реквизитов
- Искать связанные отчеты и обработки
- Анализировать использование в документах

#### Общие модули (CommonModules)
- Использовать `get_1c_examples` для проверки правильности кода
- Проверять вызовы процедур и функций через `search_metadata`
- Использовать `get_1c_syntax` для проверки синтаксиса конструкций

#### Обработки и отчеты (DataProcessors, Reports)
- Проверять формы и модули на корректность
- Искать связанные объекты метаданных
- Проверять СКД (систему компоновки данных) в отчетах

### Примеры использования инструментов

#### Перед изменением справочника:
```
/search_metadata query="Номенклатура" metadataType="Catalogs"
/find_object_by_name objectName="Номенклатура"
```

#### После изменения XML или BSL файла:
```
Использовать инструмент 1c-syntax-checker для проверки синтаксиса
```

#### При написании кода 1С:
```
/get_1c_syntax construct="Если"
/get_1c_examples topic="работа с датами"
/search_1c_help query="СтрНайти" category="функция"
```

### Частые ошибки и как их избежать

#### Ошибки в XML метаданных:
- **Проблема**: Некорректная структура XML
- **Решение**: Всегда проверять синтаксис через `1c-syntax-checker`

#### Ошибки в коде 1С:
- **Проблема**: Неправильный синтаксис конструкций
- **Решение**: Использовать `get_1c_syntax` для проверки и `1c-syntax-checker` для BSL файлов

#### Ошибки в зависимостях:
- **Проблема**: Нарушение связей между объектами
- **Решение**: Использовать `search_metadata` для анализа

#### Ошибки в типах данных:
- **Проблема**: Несоответствие типов
- **Решение**: Проверять типы через `search_1c_help`
